# Independent runtime compatibility audit

Audited 2026-09-28, read-only except this report. No build, device connection, flash, reset, or external service request. Scope excludes BSP/ButtonTest and media backend changes assigned to the hardware/storage reviewers. Paths below are relative to `ports/waveshare-1.75/firmware/brookesia` unless stated otherwise. This is a source-level compatibility assessment, not proof of runtime operation.

## P1/P2 findings

No additional confirmed P1/P2 **1.75-to-1.75C runtime compatibility defect** found in the reviewed remainder. Do not interpret this as a clean device test or as validation of concurrently changing hardware/storage implementations. No speculative code change is recommended from this audit.

## Evidence and retained behavior

- **Display/GUI:** `main/main.cpp:51,389,396,425,436` retains a 20 KiB internal LVGL stack, internal 12-row RGB565 draw buffer (11,184 bytes), 466x466 geometry, rotation 0 and mirror-X/mirror-Y touch configuration. The even-boundary invalidate adjustment remains appropriate for CO5300. The internal stack is essential because app callbacks, including Round Wing progress saves, perform NVS/filesystem operations with flash cache disabled. Preserve it. Physical touch orientation remains an on-device check; it cannot be proved from identical controller part numbers alone.
- **Framework/LVGL:** `ports/waveshare-1.75/examples/esp-idf/03_esp-brookesia/components/brookesia_core/idf_component.yml:1,24` explicitly pairs Brookesia `0.6.0-beta2` with LVGL `9.4.*`; `dependencies.lock` resolves 9.4.0 and ESP-IDF 5.5.5. All 36 LVGL calls used by repository `src/game_view.cpp` and `components/round_wing/round_wing_app.cpp` were found in installed LVGL9.4 headers by a local symbol scan. No 9.5-only API dependency found. This is declaration presence, not a compile or visual regression test; root must still build and run its game regression. Compiling all assets with one selected LVGL version avoids mixing precompiled font/image ABIs.
- **QMI8658/Gravitysphere:** `components/Gravitysphere/Gravitysphere.cpp:59,71` uses the BSP I2C bus, HIGH address (0x6B) and GPIO0 active-low calibration, all consistent with the C evidence in `/tmp/roundwing-port-hardware-audit.md`. No GPIO39/40/42 or SD pin assumptions were found here. Sensor-axis sign/orientation, calibration while stationary, and app reopen remain physical tests. Crosshair is a display/touch app with no separate IMU/pin dependency (`components/Crosshair/Crosshair.cpp:91,102`).
- **PMU:** `components/system_status/system_status.cpp:31,40,102,657` identifies AXP2101 at 0x34/ID 0x4A and preserves the five narrow charger/TS field updates already matched against the official C example by the hardware audit. No extra supply-rail or shutdown-pin change was found outside BSP. These are real startup register writes: 50 mA precharge, 400 mA charge, 25 mA termination, 4.2 V target, TS disabled. Retaining them matches source/reference, but does not establish suitability of an unknown attached battery.
- **Xiaozhi identity/provisioning:** `components/XiaozhiApp/XiaozhiActivationClient.cpp:102,274` and `components/esp_xiaozhi_safe/esp_xiaozhi/src/esp_xiaozhi_board.c:29,167` use `board/uuid` in NVS and the device MAC; board JSON remains `generic`/`esp32s3`, not a non-C board pin profile. Thus there is no hard-coded non-C server target to substitute. Preserved UUID/MAC do not guarantee that an existing cloud binding survives migration; actual server acceptance is unknown until authorized connectivity testing.
- **Xiaozhi OTA semantics:** `components/XiaozhiApp/XiaozhiApp.cpp:1338` calls the service's `/ota` information endpoint for activation/transport metadata; the component can parse a firmware offer (`esp_xiaozhi_info.c:382`) but this firmware has no `esp_ota_begin`, `esp_ota_set_boot_partition`, or `esp_https_ota` execution path in reviewed main/components. A single factory app is therefore compatible with current application behavior. Describe OTA firmware updating as unavailable; do not advertise `/ota` provisioning as update support. No need to add OTA slots solely for AIChats.
- **Xiaozhi audio/resources:** `XiaozhiAudioProcessor.cpp:384,448,455` locates speech models by partition label `model`, feeds `MMR`, and enables AEC; no old fixed model offset remains. `XiaozhiApp.cpp:1857,1872,1888` uses internal input/control stacks and explicit PSRAM encoder/playback stacks; the latter terminate with `vTaskDeleteWithCaps`. NVS/history operations occur on the internal control task. `XiaozhiClient.cpp:289` decodes Opus into the physical 24 kHz playback rate. C microphone/reference wiring was assessed separately by hardware audit; raw slot ordering and AEC performance still need measurement.
- **Chinese assets:** `sdkconfig.defaults:78,79` selects Ni Hao Xiao Zhi and Chinese UI. `XiaozhiUi.cpp:29,394` loads `/spiffs/xiaozhi/font.bin` into PSRAM (up to 4 MiB) and falls back to a compiled basic font if unavailable. Successful fallback is not evidence of complete Chinese glyph coverage. The actual generated SPIFFS image must include the common font and activation prompts; model image must contain the selected WakeNet and fit the 0xF0000 partition.
- **NVS/settings:** `main/main.cpp:498` returns NVS errors without erasing data. `system_status.cpp:62,779` and `Settings/ui/WlanPage.hpp:164` agree on `storage/wifi_en` as i32; absent key defaults Wi-Fi off, so preserving raw NVS does not promise auto-connection from a different factory schema. `board/uuid` is reused; Round Wing has separate `roundwing/unlocked` u8 with value validation. No whole-partition NVS erase call was found in main/components. Brightness/volume controls target BSP state and do not supply a general migration mechanism for older firmware settings.
- **Time:** `Settings/Settings.cpp:38,47,372` registers SNTP after obtaining an IP and applies CST-8; `esp_xiaozhi_info.c:353` also accepts server time. The status bar is not limited to boot-relative time once network synchronization succeeds. Network unavailable/blocked NTP remains normal unsynchronized-clock behavior.

## Required release/runtime checks, not established by this audit

1. Inspect final effective sdkconfig/manifest, not only defaults: 32 MiB flash, 8 MiB octal PSRAM, selected UART-free USB Serial/JTAG console, final model/resource/media addresses and lengths. A copied stale sdkconfig can override defaults.
2. Build all applications against the selected core/LVGL and verify the registry actually contains all 14 apps; symbol presence alone cannot establish successful linking or rendering.
3. Measure internal heap/largest block and stack headroom during AIChats connection/AFE, Recorder, video and repeated app transitions. The 4 KiB reserved-internal setting is not a demonstrated headroom guarantee. Full Chinese font preloading, LVGL draw workers, Wi-Fi/TLS, audio DMA and AFE compete for RAM; source inspection cannot establish the peak.
4. Verify new model/resource images, not old factory images, are packaged for the new partitions. Preserve NVS through migration but document possible reconfiguration/rebinding. Confirm resources fail non-destructively if omitted.
5. On authorized hardware: verify display/touch corners, motion direction and calibration, USB console after boot, Wi-Fi provisioning/reconnect, clock, cloud activation, wake word, two-microphone capture/reference cancellation and audio app ownership transitions. No such validation occurred here.

No product source was modified by this audit.
