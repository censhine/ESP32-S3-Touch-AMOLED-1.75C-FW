# 2026-09-28 运行问题排查

本记录对应首次安装后用户反馈的 MusicPlayer 声音和 AIChats 连接／唤醒问题。

## MusicPlayer

- 预置 `channel-test.wav` 是 2 秒、44.1 kHz、16 位双声道测试音，左右通道分别为 440/880 Hz。用户确认听到约两秒蜂鸣，与素材一致；它不是歌曲。
- 原界面把真实文件时长写死为 60 秒，频谱动画结束还会切换／重播曲目，且未同步播放器 EOF，因此容易让人误以为持续播放却没有声音。
- 本次修复读取有效 PCM WAV 的实际时长，在播放器结束／错误时停止界面动画并清除播放状态。MP3 等未知总时长显示 `--:--`，不编造时长。暂停恢复保留已播时间，拒绝的播放请求保留原状态。
- 状态在 LVGL 线程每 100 ms 检查。排队开始有 1 秒宽限，以覆盖短音频未被轮询到 PLAYING 的情况；底层 API 没有请求编号，不能据此提供逐采样进度。
- 未修改音频引脚、ES8311/ES7210 驱动或媒体分区。

## AIChats

- 用户配置 WLAN 后，在旧版本重启后的实测中已到“待命”。日志确认 HTTPS／WebSocket 证书验证通过，服务连接及 AFE 初始化完成。
- 旧版本的启动提示音任务创建失败。提示音需连续 24 KiB 内部栈，当时最大可用内部块只有 18 KiB；语音任务建立后内部堆仅余约 8.8 KiB、最大块 3.5 KiB。
- 本次选择 `CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC=y`，把 TLS 数据分配到 8 MB PSRAM，给内部任务栈留空间。证书验证、TLS 记录长度以及任务栈放置策略保持原配置。此设置让 TLS 数据进入外部 RAM，后续版本若启用内存加密或改变安全要求需重新评估。
- 加入仅含 HTTP 状态／长度、失败时内存余量的诊断日志，不记录服务凭据或响应正文。
- 旧版本随后还出现重连及 TLS 握手错误；不能仅凭此前的“待命”认定连接长期稳定。
- 后续新版本日志确认 `Wake word detected: 你好小智`、发送语音帧、收到服务器 TTS 回复；用户也确认“小智可以了”。语音任务建立前内部堆约 46 KiB、最大块 32 KiB，较旧版改善。
